# Local demonstration continuity during communications interruptions

ARES maintains its **fictional-data demonstration workflow** during an external
communications interruption by running a prepared React interface and the
FastAPI/Python engine on the same computer through its loopback interface.
Synthetic scenarios, validation, charts, timelines, the deterministic Copilot,
Wellness summaries and JSON report generation all use installed code and assets;
they require no CDN, cloud inference or AI API. Reports can be downloaded locally.

NASA citations remain visible as background references, but opening their live
pages and fetching optional NASA research data need connectivity. Research failures
are isolated from the mission workflow and never replaced with invented results.
The local server must remain running. The Render-hosted demonstration still needs
a connection to Render: no browser-only offline engine or PWA fallback is claimed.
This experimental synthetic prototype is not medically validated, flight-qualified,
NASA-authorized software or evidence of actual spacecraft operational capability.
